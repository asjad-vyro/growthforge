# GrowthForge

Trend-driven growth marketing for early-stage founders. Onboard your product + brand kit →
scrape your market's Instagram / X / LinkedIn conversation via Apify → LLM trend analysis →
generate on-brand **tweets, carousels, image ads and a UGC-style reel** grounded in what's
actually working.

**Five vendors, nothing else:** Supabase (Postgres/auth/storage/realtime) · Vercel (deploy + cron) ·
ImagineArt MCP (all media generation) · OpenRouter (all LLM calls) · Apify (scraping).

Image ads, carousels and reels are generated by three pipelines ported from
[Forge](https://github.com/Vyro-ai/forge) (ImagineArt's internal ad-automation engine) —
`src/lib/generation/{image-studio,carousel-studio,video-studio}/` — re-pointed at imagine-mcp
instead of Forge's own fal-based backend. Each is a deliberately smaller slice of Forge's real
surface (its core generic engine, not every bespoke skin/template it also ships) — see the doc
comment at the top of each `index.ts` for exactly what was and wasn't ported, and why. Every
imagine-mcp call runs **sequentially**, never in parallel: the server throttles concurrent
generations per user (a Redis-backed limiter, ~2 in flight by default), which is far below the
fan-out Forge itself fires against a raw fal queue.

## Architecture in one paragraph

A `jobs` table in Postgres is the queue (`FOR UPDATE SKIP LOCKED` claiming). `/api/jobs/tick`
is the worker — poked fire-and-forget after every enqueue, swept every minute by Vercel Cron,
with a watchdog that reclaims jobs whose worker died. Apify actor runs are async: their webhook
(`/api/webhooks/apify`) enqueues the next pipeline step, so nothing ever blocks on a long
external job. Pipeline: `run.start` → 4× scrape → normalize + engagement z-scores → stratified
sample → map-reduce trend analysis → TrendReport with `content_angles` → asset fan-out (tweets /
Image Studio ad backgrounds+copy baked in by the model / Carousel Studio slide sets / a single
Video Studio reference-to-video call per reel — no separate TTS/transcription/compose chain).

## Setup

### 1. Supabase
1. Create a project at supabase.com.
2. Auth → Providers: enable **Email** (magic link). Optionally Google (add OAuth credentials).
3. Auth → URL Configuration: set Site URL to your app URL, add `https://<app>/auth/callback` to redirect URLs.
4. Copy Project URL, anon key, service-role key, and the **direct** DB connection string.

### 2. Environment
```bash
cp .env.example .env.local   # fill everything in
```
- **Supabase / DATABASE_URL / APIFY_TOKEN / OPENROUTER_API_KEY** — straightforward, see the
  comments in `.env.example`.
- **IMAGINE_MCP_URL** — `https://mcp.imagine.art` (production) or `https://dev-mcp.imagine.art`
  (beta/dev) — both are real, hosted instances of
  [Vyro-ai/imagine-mcp](https://github.com/Vyro-ai/imagine-mcp).
- **IMAGINE_MCP_ACCESS_TOKEN / IMAGINE_MCP_ORG_ID** — there is no service-account key; auth is
  a real ImagineArt user-session OAuth grant (org + subscription checked per call). Access
  tokens live ~1 hour; refresh tokens live 30 days and ROTATE on every refresh. The pipeline
  self-refreshes: the session lives in the `app_secrets` table and
  `src/lib/imagine-mcp/client.ts` rotates it automatically on 401. One-time setup:
  ```bash
  node scripts/imagine-login.mjs
  # → browser opens; log in with the ImagineArt account whose org should be billed.
  #   The script prints the org listing → copy the id into IMAGINE_MCP_ORG_ID, and the
  #   access token into IMAGINE_MCP_ACCESS_TOKEN (bootstrap fallback only).
  node --env-file=.env.local scripts/seed-imagine-tokens.mjs
  # → stores the session (incl. refresh token) in app_secrets; from here on it is
  #   self-sustaining as long as ANY imagine call happens at least once every 30 days.
  # If the grant fully lapses (30 days idle / revoked), generation throws with a message
  # telling you to re-run these two commands.
  ```
- **IMAGINE_MCP_FOLDER_ID** — optional, from `select_folder`; omit to use the workspace root.

**Pinned tools, not runtime discovery.** `src/lib/imagine-mcp/client.ts` never calls
`list_tools()` — it calls `generate_image` / `generate_video` / `fetch_status` directly by name.
That's a deliberate choice (no LLM is picking tools at generation time, so there's nothing to
feed a schema to), but it means MCP's only contract is whatever `list_tools()` returns *today* —
unlike a versioned REST API, ImagineArt can rename an arg with no warning and a call just starts
400ing. Two scripts keep that honest:
```bash
# One-time, after you have a working IMAGINE_MCP_ACCESS_TOKEN — captures the 3 pinned tools'
# schemas into imagine-tools.snapshot.json. Commit the result.
node scripts/dump-imagine-tools.mjs

# Re-run any time (also runs nightly in CI, .github/workflows/imagine-tools-drift.yml, once
# IMAGINE_MCP_URL / IMAGINE_MCP_ACCESS_TOKEN are added as repo secrets) — diffs live list_tools()
# against the committed snapshot and fails loudly if anything changed.
node scripts/check-imagine-tools-drift.mjs
```
`imagine-tools.snapshot.json` is committed (captured against the live server); the CI drift job
needs `IMAGINE_MCP_URL` / `IMAGINE_MCP_ACCESS_TOKEN` as repo secrets to run.

### 3. Database + storage
```bash
# DDL uses the SESSION pooler URL (MIGRATE_DATABASE_URL, port 5432):
export DATABASE_URL=$(grep '^MIGRATE_DATABASE_URL=' .env.local | cut -d= -f2-)
npx drizzle-kit migrate                            # applies drizzle/* (tables + RLS + realtime)
# (fresh rebuild without the drizzle/ folder? use `npx drizzle-kit push --force`
#  then `node --env-file=.env.local scripts/apply-rls.mjs` — same end state)
node --env-file=.env.local scripts/setup-buckets.mjs   # creates the three private buckets
```

### 4. Run locally
```bash
pnpm dev
```
The Apify webhook needs a public URL — use `ngrok http 3000` (or similar) and set `APP_URL`
to the tunnel URL. Without a tunnel you can still test scraping by hitting the tick worker
manually after an actor finishes: the cron sweep also picks up a fallback poll… but webhooks
are the intended path. Trigger the worker by hand any time:
```bash
curl -X POST localhost:3000/api/jobs/tick -H "Authorization: Bearer $CRON_SECRET"
```
There's no cron running locally at all — if a run looks stuck, it's usually just waiting on a
tick; re-run the `curl` above (a `queued` job with a growing `attempts` count and an `error` in
the `jobs` table means it's actually failing, not stuck — a blank `APIFY_TOKEN` is the usual cause).

To skip the Supabase login entirely while testing (fixed dev user + workspace, created lazily
on first request), set in `.env.local`:
```bash
DEV_SKIP_AUTH=true
```
Never set this outside local dev — `src/proxy.ts` and `requireUser()` both gate on it being
exactly `"true"`.

### 5. Deploy
1. Push to GitHub → import in Vercel (needs **Pro** for the every-minute cron in `vercel.json`).
2. Add all env vars (set `APP_URL` to the production URL).
3. Set `CRON_SECRET` in Vercel env — Vercel Cron automatically sends it as a Bearer token.

## Verify at implementation time (pinned externals move)

- **ImagineArt MCP auth** (`src/lib/imagine-mcp/client.ts`) — self-refreshing (see "2.
  Environment"): 1h access tokens, 30-day rotating refresh tokens stored in `app_secrets`.
  This is the "central billing" shape (one server-side session, one credit pool, no per-user
  linking) — confirm with the ImagineArt/Vyro team before relying on it at real volume:
  whether a single rotating grant is acceptable long-term, and whether one account fronting
  many end users is within the intended terms of use rather than something that gets
  rate-limited once noticed.
- **Video Studio has no product screenshot to ground on** (`src/lib/generation/video-studio/`)
  — Forge's templates are built to reproduce a real product screenshot on the laptop-reveal
  shot; GrowthForge has no screenshot library (unlike Forge's feature packs), so no reference
  image is attached and the model invents a plausible UI instead. Expect lower UI fidelity than
  Forge's own output until GrowthForge has a way to capture/store real product screenshots.
- **Apify actor input shapes** (`src/lib/apify/actors.ts`) — env-overridable; re-check
  pricing/inputs in the Apify dashboard.
- **OpenRouter model slugs** (`src/lib/llm/models.ts`) — env-overridable
  (`LLM_MODEL_*`); check openrouter.ai/models for current best slugs.

## Cost controls

- `SCRAPE_MAX_ITEMS_PER_PLATFORM` (default 200) caps pay-per-result actor spend.
- `TREND_CORPUS_CAP` (default 600) caps analysis tokens.
- One pipeline run per project per 7 days unless the user explicitly overrides.
- Workspace monthly budget (Settings) is checked before every paid step; every paid call is
  logged to `usage_events`. A full default run ≈ **$3–4** marginal.
